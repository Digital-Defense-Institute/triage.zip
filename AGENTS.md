# triage.zip

Static GitHub Pages site and Velociraptor offline collector build pipeline.

## Supported outputs

- Windows x64: `Velociraptor_Triage_Collector.exe`
- Linux x64: `Velociraptor_Triage_Collector_Linux`
- macOS Intel: `Velociraptor_Triage_Collector_macOS`
- macOS Apple Silicon: `Velociraptor_Triage_Collector_macOS_ARM`

Windows x86 is retired: Velociraptor 0.77.3 removed the `Windows_x86`
collector target. Keep build scripts, configuration, release uploads, README,
and site download links consistent with these four outputs.

## Build contracts

- `lib/collector_common.sh` owns numeric release selection and direct binary
  downloads. Support raw and gzip assets; pin embedded macOS binaries to the
  exact host version. Validate downloaded bytes before decompression.
- Verify both downloaded artifact bundles on both build paths. Upstream 0.77.3
  made advisory warnings fatal; use the shared verifier helper to retain fatal
  YAML/VQL errors while allowing upstream permission-declaration warnings.
- Linux CI uses `build_collector.sh`; native macOS uses
  `build_collector_macos.sh`. Both must reject collector stubs and ad-hoc sign
  both macOS outputs.
- Scheduled CI skips unchanged upstream versions/artifact ETags. Push, PR,
  and manual runs build. The pre-build policy in `scripts/ci_policy.sh` permits
  publication only on successful `main` runs with upstream version/ETag changes,
  collector input changes across the whole push, or manual dispatch. Build scripts
  must not overwrite change-detection flags. Commit metadata after publication.
- `data/velociraptor-version.json` describes the published build. Do not commit
  metadata generated by local validation or claim a new version is published
  before the release exists.
- Every built Windows and Linux collector must pass `windows_validate` and
  `linux_validate` on separate disposable hosted runners before publication.
  Run the exact executables with their embedded production configurations;
  do not substitute reduced test specs. The Linux workload uses root and the
  production `Linux.Triage.UAC` `_All` targets on pinned `ubuntu-24.04`.
  The publish job must use the same immutable build artifact and verify both
  executable SHA256 hashes against their successful validation jobs.
- Stage only the four collector binaries, version metadata and checksums for CI
  handoff. Never upload the build datastore or generated server configuration.
  Upload only the redacted validation report, never collection ZIPs or raw logs.

## Validation

Before adding a custom artifact, check the supported Velociraptor release's
built-ins, the current upstream sources, and the Artifact Exchange. Prefer
configuring existing artifacts. General acquisition features and exclusions
belong in the upstream Triage Artifact project; keep triage.zip focused on
artifact selection, collection policy, and packaging. Establish the precise
remaining gap before proposing a local implementation or upstream contribution.

Run `bash tests/collector_common_test.sh`, shell syntax checks, and
`actionlint .github/workflows/ci.yml` when available. For integration testing,
copy the scripts, `lib/`, `config/`, and `data/` to a temporary directory and
build there: builds download tools and create a datastore and server config
containing private keys. Never commit those generated files. Building a
collector is safe validation; executing its collection workload against the
host requires separate authorization.

`scripts/run_windows_collection.ps1` deliberately refuses execution outside a
GitHub-hosted Windows runner. Its process helper can be unit tested without
running collection. `scripts/validate_windows_collection.py` validates existing
collection containers without executing them. Keep regression fixtures synthetic;
do not commit real host evidence. Run PowerShell tests with `pwsh` installed and
exercise the full production collector through the PR's Windows CI job.

`scripts/run_linux_collection.py` requires root on a hosted Linux runner,
isolates the collection process group, enforces its timeout, and cleans up
evidence. `scripts/collection_validation.py` owns shared container checks;
`scripts/validate_linux_collection.py` adds UAC source, production parameter,
upload and semantic system-baseline checks. Keep host guards out of pure helper
tests so synthetic executables can test process failure and timeout safely.

Do not accept `FINISHED` or exit code zero as proof of complete acquisition.
Velociraptor 0.77.3 can retain read failures in an `Upload.Error` response while
the collection finishes. A zero-byte ZIP member whose `StoredSize` matches zero
can still represent a failed nonempty-file acquisition. Preserve those errors
and investigate their cause before introducing any narrowly scoped exception.
Upstream omits `StoredSize` when zero; accept that omission only for an actually
empty member, and require separate verified nonempty evidence.

The only accepted upload-error exceptions are explicitly marked ZIP directories
with no stored bytes and Windows `ERROR_INVALID_FUNCTION` (`Incorrect function`)
or Linux `EISDIR` (`is a directory`) in their respective validators.
Adaptive triage targets can select directories; upstream deliberately does not
retry these reads through NTFS. Report such entries as directory skips and never
count them as file evidence. Keep regular-file, partial, unknown and size errors
fatal. Test these exceptions through hosted runs as well as synthetic ZIPs.

Linux UAC `Details.Stat` may omit or misattribute the link metadata needed to
classify failed targets. Do not infer a symlink from an error message alone.
The guarded runner may inspect failed source paths with `lstat`/`stat`, store
temporary facts inside its private collection directory, and bind those facts
to the exact archive SHA256. Only explicitly supplied matching facts can permit
symlinks to directories, `/etc` configuration or systemd unit links pointing to
`/dev/null` or explicit kernel device/FIFO/socket types, or dangling `/etc` links
as separately reported skips. Require matching positive link size and exact
errors, with no partial output. A vanished `/tmp` or `/var/tmp` target is an
explicitly counted exception only with matching original positive-size Glob
metadata, fresh same-runner ENOENT and no stored output. Other missing files,
existing regular-file read errors and unknown types remain fatal. Static archive validation
must never inspect source paths on the current host. These facts establish
post-collection state, not historical target immutability. Never upload facts files.

Windows temporary disappearance uses the same explicit archive-bound facts model.
`scripts/windows_source_facts.py` probes only the validator's eligible ordinary
local temp paths on the hosted Administrator runner. Reject raw NTFS/VSS/device
and UNC paths, DOS device aliases, traversal and ADS before any probe. A skip
requires fresh WinError 2/3, the exact pre-write error, no stored output, and
matching original positive-size file metadata. Never generalize this to all
missing executable paths or waive a regular-file read/partial-write failure.

Check all four output formats and both macOS signatures. A local macOS build
does not prove Linux CI signing works; require the PR build to pass as well.
For site edits, check download targets, OS tabs, and narrow-screen layout.

`tests/test_motw_collection.py` runs real NTFS image tests when
`VELOCIRAPTOR_BINARY` and `VELOCIRAPTOR_NTFS_FIXTURE` are set. The latter must
be the SHA256-pinned upstream v0.77.3 `test.ntfs.dd`; tests modify only temporary
copies. CI runs these after building and before any release mutation. Preserve
this separation from executing a collector against the host.

Parser runtime measurements and exact sanitized reports are under
`docs/benchmarks/`. Compare first collections with first collections: repeated
runs on one runner have a large warm-cache effect. Keep process runtime separate
from validator/cleanup overhead and identify which proposed features were enabled.
The 2026-11-06 experiment covered five parsers only, excluding MOTW and future
upstream acquisition changes; it does not establish workstation runtime bounds.

## Collector changelog

`data/changelog.json` is the single changelog source. Run
`python3 site/render_changelog.py` to regenerate `CHANGELOG.md` and
`changelog.html`; `--check` verifies that both outputs are current. The generator
belongs under `site/`, not `scripts/`, so site-only edits do not become collector
publication inputs. Keep a prominent changelog link beside the downloads.

Document collector behavior/platform/default changes as undated proposals during
review. Promote them to a dated entry only after publication is verified, using
the UTC publication date and source links. Historical backfill uses verified
main-branch dates and must retain the visible caveat about publication timing.
Keep upstream-only work and unmerged branches out of dated history. Visually
check platform filtering, anchor links, and desktop/mobile layouts after site edits.
